````text
OVERDARE Studio에 임포트할 수 있도록 Blender 에셋을 FBX로 변환해줘.
아래 제약은 전부 실측으로 확인한 것이니 반드시 지켜라. 하나라도 어기면 임포트가 거부되거나
텍스처가 깨지거나 지오메트리가 파편이 된다.

## 소스
C:\Users\29\Desktop\blender\ColdWarBerlin_AssetPack\00_Source_Blender\cold_war_berlin_asset_library.blend

이 .blend에는 베를린 장벽 맵의 에셋들이 들어 있다. 한 에셋이 여러 파트(오브젝트)로 되어 있고,
이름 규칙은 "<에셋명>.<NNN>__<파트>" (예: HQ_Trabant.001__002)다. 같은 에셋이 맵에 여러 번
복제 배치돼 있으므로, 한 에셋당 파트가 가장 많은 인스턴스 하나만 골라 변환한다
(export 시 "<에셋명>" 접두사로 매칭 → 인스턴스명 그룹 중 파트 최다, 동수면 최소 번호).

## 출력
- 위치: C:\Users\29\Desktop\MeshTest\Converted\<에셋명>_overdare.fbx
- 형식: FBX, 텍스처 임베드(embed_textures=True, path_mode='COPY')
- 에셋당 최종 파일이 30,000 삼각형을 넘으면, 30k 이하 조각들로 나눠 여러 파일로 출력하고
  각 조각의 "에셋 중심으로부터의 오프셋(Blender m, Z-up)"을 리포트해라. 재조립에 필요하다.

## OVERDARE 하드 제약 (절대 규칙)

1. **파일당 삼각형 30,000개** — 파트 합계가 아니라 파일 전체 삼각형 총합이 30k를 넘으면 임포트가
   "exceeds the maximum allowed polygons"로 거부된다. 파트를 여러 개 담아도 총합 기준이다.

2. **MeshPart당 텍스처 1장** — OVERDARE 메시는 텍스처를 딱 하나만 표시한다. 재질(머티리얼)이
   여러 개고 각자 다른 이미지를 쓰면, 임포트 후 그 중 하나만 나오고 나머지 면은 엉뚱한 그림이
   된다. → 재질이 여러 개면 반드시 **재질별로 오브젝트를 분리(separate by material)** 해서
   각 조각이 재질 1개 = 텍스처 1장을 갖게 하라. (조각들은 위 30k 규칙에 맞춰 파일로 묶는다.)

3. **단위/축**: OVERDARE는 Y-up, cm. Blender는 Z-up, m. 좌표 변환은 (X,Y,Z)_ovdr = (x, z, y)*100.
   크기 자체는 export가 맞춰주지만, 오프셋 리포트는 Blender m(Z-up) 그대로 주면 된다.

4. **텍스처 해상도**: 4K/8K는 임포터가 메모리 부족으로 죽는다. 1024로 다운스케일해라
   (512가 공식 권장이지만 1024가 디테일/용량 균형).

## 익스포트 함정 (전부 실제로 겪은 것 — 반드시 처리)

A. **크기가 오브젝트 트랜스폼에 들어있는 에셋** — 일부 에셋은 지오메트리를 원본(raw) 스케일로 두고
   오브젝트 스케일로 줄여놨다(예: 관람차가 버텍스는 181m인데 스케일로 28m). 그대로 export하면
   스케일이 사라져 6배 크게 나온다. → **export 전에 반드시 make_single_user 후
   transform_apply(location, rotation, scale)** 로 트랜스폼을 지오메트리에 구워라.
   export 후 실제 바운딩박스가 씬 바운딩박스와 5% 넘게 다르면 실패로 간주하고 다시 해라.

B. **FBX는 Principled BSDF의 Base Color에 연결된 이미지만 내보낸다** — 다음 두 경우 텍스처가
   통째로 사라져 무텍스처로 나온다:
   - 이미지 노드가 어디에도 안 연결됐거나 다른 소켓에만 연결된 경우 → 색상맵을 Base Color에 연결.
   - **Unlit/Emission 구성**(photogrammetry 스캔에 흔함): TEX_IMAGE → EMISSION → MIX_SHADER,
     Principled 노드 자체가 없음. → Principled를 새로 만들어 이미지를 Base Color에 연결하고
     Material Output의 Surface에 물려라.

C. **노멀/러프니스/AO 맵을 같이 내보내지 마라** — 색상맵 외의 이미지가 FBX에 섞이면 OVERDARE가
   그걸 텍스처로 골라 표면이 노이즈가 된다. → 각 재질에서 색상맵(baseColor/diffuse/albedo)만
   남기고 normal/roughness/metallic/AO/displacement 이미지 노드는 제거해라.

D. **procedural(절차적) 재질은 베이크해야 한다** — Base Color가 이미지 직결이 아니라 MIX_RGB/노이즈
   체인을 거치는 재질(예: 벽돌 벽)은 FBX가 표현 못 한다. → 이런 재질은 Cycles diffuse 베이크로
   단일 아틀라스 이미지를 굽고, 그 이미지를 Base Color에 연결한 **단일 재질로 교체**해라.
   베이크 이미지 이름은 반드시 "<에셋명>_T"처럼 **에셋마다 유니크**하게 — 전부 "BakedDiffuse"로
   같으면 임포트 시 이름 충돌로 어느 텍스처가 어느 메시 건지 알 수 없게 된다.

E. **path_mode='COPY'는 디스크의 원본 파일을 임베드한다** — img.scale()로 메모리만 줄여도
   디스크의 8K 원본이 그대로 임베드돼 파일이 수십 MB가 된다. → 스케일한 픽셀을 디스크에 PNG로
   저장(img.save)하고 img.filepath를 그 파일로 재지정한 뒤 export해라.

F. **photogrammetry 스캔은 데시메이션하면 파편이 된다** — 이게 가장 중요하다. 수십만~백만 삼각형짜리
   스캔 메시(교회, 전승기념탑 등)를 collapse 데시메이션으로 30k에 맞추면, UV 지표상으론 멀쩡해
   보여도 실제 렌더는 파란 유리 파편 덩어리가 된다. 면이 뒤집히고 찢어진다.
   → **스캔 메시는 절대 데시메이션하지 마라.** 대신 원본 지오메트리를 그대로 두고 공간적으로
   잘라(bisect) 각 조각이 30k 이하가 되게만 나눠라. 조각 수가 많아도(백만 삼각형이면 34+조각)
   그게 유일하게 깨지지 않는 방법이다. 잘라도 지오메트리는 원본이라 안 부서진다.
   ※ 반대로, 스캔이 아니라 원래 저폴리 파트 여러 개로 된 에셋(예: 창문/벽 재질별로 나뉜 건물)은
     데시메이션 없이 재질 분리만 하면 깨끗하다.

## 에셋 분류와 전략 (판단 기준)

각 에셋을 열어 재질/이미지/삼각형/노드구성을 보고 아래로 분류해 처리:

- **저폴리 다재질** (재질 여러 개, 각 재질 저폴리, 스캔 아님):
  재질 분리 → 각 조각 원본 텍스처 유지 → 30k 파일로 묶기. 데시메이션 없음.

- **단일/소수 재질 + 이미지 직결 + 스캔 아님**:
  필요시 가벼운 collapse로 30k에 맞추고 원본 텍스처 유지. (스캔이면 절대 금지 — F 참조)

- **procedural 재질**: 베이크(D) → 단일 아틀라스.

- **photogrammetry 스캔**: 데시메이션 금지. bisect로만 30k 조각 분할(F). 조각 다수 허용.
  텍스처는 unlit이면 배선 복구(B), 8K면 다운스케일(E).

## 검증 (각 에셋 처리 후 반드시)

1. export한 FBX를 다시 import해서 실제 바운딩박스가 씬과 일치하는지(±5%) — A 검증.
2. 각 파일의 삼각형 총합 ≤ 30,000 — 1번 규칙.
3. 각 조각의 이미지가 정확히 1개, 그게 색상맵인지 — B/C 검증.
4. 조각 파일들의 이미지 이름이 유니크한지 — D 검증.
5. 리포트로 남겨라: 에셋명 / 파일 목록 / 각 파일 삼각형수 / 각 조각 오프셋(Blender m) /
   텍스처 이름 / 적용한 전략.

먼저 소스 .blend를 열어 에셋 목록과 각 에셋의 재질/삼각형 현황을 요약해서 보고하고,
어떤 에셋을 어떤 전략으로 처리할지 계획을 먼저 제시해라. 내 승인 후 변환을 시작해라.
````

## 참고 — 왜 이 프롬프트가 이렇게 상세한가

이 제약들은 하나하나가 며칠간의 실패로 확인된 것이다:

| 함정 | 겪은 증상 |
|---|---|
| 30k 파일당 제한 | Bulk Import도 30k 초과 시 거부 (메시 200개여도 총합 기준) |
| 텍스처 1장 제한 | 스타디움 텍스처 99장 → 1장만 나옴 |
| A 트랜스폼 | 관람차가 6배 크게 임포트됨 |
| B unlit | 전승기념탑 텍스처가 통째로 사라짐 |
| C 노멀맵 | 표면이 노이즈로 렌더됨 |
| D procedural | 알트바우 벽돌이 무텍스처 |
| E path COPY | 조각당 17MB, 총 898MB |
| F 데시메이션 | 교회·전승탑이 파란 파편으로 부서짐 |

이미 동작하는 헤드리스 파이프라인(`scripts/prepare_mesh.py`, `split_asset.py`, `export_asset.py`)에
위 로직이 대부분 구현돼 있으니, 블렌더 MCP 에이전트가 참고할 수 있으면 참고하라고 해도 된다.
